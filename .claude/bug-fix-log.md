# Bug 修复记录

## 2026-08-25：PDF 上传期间页面没有状态反馈

- 现象：点击“开始转换”后按钮只会变灰，大文件上传完成前页面没有进度或阶段说明，用户无法判断请求是否生效。
- 原因：前端使用 `fetch` 上传 multipart 请求，并且只在 `POST /api/v1/jobs` 完整返回后渲染任务面板；浏览器上传文件的等待时间完全不可见。
- 修复：上传请求改为支持 upload progress 事件的 XHR；提交后立即展示上传状态、实际字节与百分比，上传完成后切换为任务创建/转换状态，同时支持取消尚未完成的上传。
- 验证：新增嵌入式 UI 回归检查，确保初始状态在等待请求前渲染且保留进度与取消反馈；同时执行 JavaScript 语法检查、Go 全量测试与容器构建。

## 2026-08-25：根页面循环重定向

- 现象：访问 `/` 时 `http.FileServer` 在 `/` 与 `/index.html` 的规范化逻辑之间持续返回 301。
- 原因：UI handler 将根路径手动改写为 `/index.html`，而 `FileServer` 会把显式 `index.html` 再重定向回目录路径。
- 修复：根页面直接从嵌入文件系统读取并返回，CSS/JS 等静态资源继续交给 `FileServer`。
- 验证：浏览器网络记录不再出现循环，根页面能够渲染登录界面。

## 2026-08-25：中文文件名导致 EPUBCheck 误报失败

- 现象：中文文件名 PDF 完成全部页面转换和 EPUB 打包后，任务在规范校验阶段失败；UI 只显示“EPUB 未通过规范校验”。
- 原因：容器未显式配置 UTF-8 locale，Java 将传给 EPUBCheck 的中文 EPUB 路径替换为问号，最终以 `File not found` 退出；生成的 EPUB 本身通过规范校验。
- 修复：校验前在任务目录内为 EPUB 创建纯 ASCII 硬链接并将该路径传给 EPUBCheck，校验后自动清理；容器同时声明 `C.UTF-8` locale，并在服务端日志保留内部失败原因。
- 验证：新增中文源路径回归测试；同一真实 PDF 生成的 177.8 MB EPUB 使用英文路径运行 EPUBCheck 5.3.0 时为 0 errors / 0 warnings。

## 2026-08-25：大型 EPUB 下载受源站公网出口限制

- 现象：177.8 MB EPUB 转换成功后下载速度只有约 0.64–1.39 MB/s，需要约 2–5 分钟。
- 原因：同一文件在服务器回环地址读取达到约 1.13–1.27 GB/s，Go、磁盘和 Nginx 均无应用层限速；瓶颈位于新加坡 VPS 到用户的公网链路。
- 修复：新增私有 Cloudflare R2 产物交付；转换完成后上传对象并删除源站副本，登录下载接口签发 15 分钟 URL 后重定向；R2 故障时保留本地下载降级。
- 验证：覆盖 R2 上传、中文下载元数据、SigV4 URL、远端删除、管理器远程产物生命周期、HTTP 302 和本地降级回归测试。

## 2026-08-25：图片型 PDF 将重复水印输出为正文

- 现象：`AI漫剧创作一本通_compressed.pdf` 转换后，阅读器左页显示源页面图片，右页重复显示 `haitianyilulu`。
- 原因：该 PDF 的中文正文只存在于整页图片，256 页文本层均为相同水印；旧预检只判断文本是否为空，水印绕过了扫描页检查，重建阶段又同时输出水印段落和页面图片。
- 修复：新增自动、可重排、固定三种模式；自动模式以主图片覆盖率和跨页文本指纹识别图片型正文并生成固定版式双页 EPUB，强制可重排时明确拒绝此类输入。
- 验证：自动检测、模式 API、固定版式 OPF/XHTML 回归测试，以及 256 页真实样本 EPUBCheck 与页面数量检查。

## 2026-08-26：公开访问前缺少资源归属、付费和滥用边界

- 现象：原任务 API 只校验会话和任务 ID，没有校验任务 owner；若直接去掉共享密码，任意访客可消耗转换资源，并可能通过获得的任务 ID 查询、取消或下载其他访客任务。
- 原因：原设计是单账号私有服务，所有任务天然属于同一主体；它不能直接扩展成匿名公网商业服务。
- 修复：增加签名访客 subject、所有任务读写的 owner 校验、IP/subject 限流、Turnstile 一次性上传票据、有限单工作器队列，以及 bbolt 持久化额度/订单/支付事件/任务扣费；任务接受时扣 1 次，失败、取消或进程重启遗留的未终态扣费幂等退款；公开模式缺少 Stripe、Turnstile、R2、HTTPS 或 Secure Cookie 时拒绝启动，R2 发布失败也禁止退回源站下载。
- 验证：新增访客会话跨重启验签、篡改拒绝、跨 owner 统一 404、无票据上传拒绝、额度不足 402、接受扣费、取消退款、队列顺序与溢出、R2 强制交付失败、Stripe webhook 验签/重放去重和 Turnstile Siteverify 回归测试。

## 2026-08-26：个人运营依赖 Stripe 与 Turnstile 账号

- 现象：公开模式虽然具备商业化与防滥用边界，但启动强制要求 Stripe 和 Cloudflare Turnstile 凭据，个人运营者可能因主体、地区或审核门槛无法上线。
- 原因：首个公开 Beta 把具体第三方 provider 写成了公开模式的必选配置，没有保留“额度账本能力”和“收款/挑战供应商”的独立选择。
- 修复：把支付和挑战分别改为 provider 配置；增加 HMAC 额度码的一次入账与跨浏览器钱包恢复，增加服务端签发/验证且拒绝重放的 ALTCHA 工作量证明，同时保留 Stripe 和 Turnstile 可选路径。
- 验证：覆盖 voucher 签名篡改、幂等入账、跨浏览器 subject 恢复、ALTCHA 过期与 replay、challenge/redeem HTTP 流程、公开配置 fail-closed 和 UI 静态资源回归。
