# 项目架构

## 项目定位

`btc-server`：可部署到服务器、带简单 Web UI 的 PDF 转 EPUB 服务。带可靠文本层的图书型 PDF 转换为可重排 EPUB 3；正文位于页面图片中或版面无法可靠重建的 PDF 转换为固定版式 EPUB 3。Go 服务同时提供 UI 所需的 HTTP API，并支持私有单账号模式或公开付费 Beta；不提供通用电子书格式互转，也不提供 OCR。

本文件用于记录项目边界、目录职责、关键架构决策和后续扩展原则。内容应以项目真实结构为准，避免只保留通用模板。

## 目录职责

### `AGENTS.md`

Agent 入口文件。用于说明项目目标、协作原则和关键文档索引。任何 Agent 开始工作前都应先阅读该文件。

### `.claude/`

项目长期上下文目录。这里保存架构、规范、协作流程和故障记录，避免重要信息散落在对话或临时笔记中。

### `docs/agents/`

可选的 Agent 操作规则目录。只有在初始化时启用 `--with-agent-ops` 才会创建。用于说明 issue tracker、triage label、领域文档读取顺序和 skill 使用方式。

### `CONTEXT.md` / `CONTEXT-MAP.md`

可选的领域上下文入口。`single` 布局使用根目录 `CONTEXT.md`；`multi` 布局使用根目录 `CONTEXT-MAP.md` 指向多个上下文；`claude-only` 布局不创建这些文件。

### `docs/adr/`

可选的架构决策记录目录。用于保存重要技术选择、替代方案和后续维护影响。

### `.agents/skills/`

可选的项目级 Agent Skills 目录。只有在项目明确需要可复用 Agent 工作流时才创建。新增 skill 时，应同步说明触发条件、输入输出、验证方式和安全边界。

## 架构原则

- 让目录结构表达职责边界。
- 优先遵循项目已有模式，不为了新功能随意引入新风格。
- 共享逻辑需要有清晰调用边界和验证方式。
- 外部服务、账号、密钥、网络访问和数据写入必须明确安全边界。
- Agent 操作规则应写入 `docs/agents/`，项目事实和长期上下文应写入 `.claude/` 或 `CONTEXT.md`，不要混淆职责。
- 项目级 skills 应保持触发条件明确，避免把泛用提示词或个人偏好写成长期能力。
- 架构变更必须同步更新本文件。

## V1 Web UI 边界

- 使用单页完成一次一个 PDF 的转换流程。
- 页面提供选择或拖放 PDF、开始或取消转换、显示转换状态或失败原因、下载 EPUB。
- 页面只展示自动确定的书名和作者，不提供元数据编辑表单。
- V1 不提供批量转换、历史记录或 EPUB 内容编辑器。
- UI 使用原生 HTML、CSS 和 JavaScript，通过 `go:embed` 与 Go 服务一同发布，不使用独立前端构建链。
- UI 只通过同源 JSON API 访问登录、转换任务和下载能力。

## V1 EPUB 元数据

- 书名优先使用有效的 PDF 标题元数据；缺失时使用去掉 `.pdf` 后缀的原文件名。
- 作者使用有效的 PDF 作者元数据；缺失时保持为空。
- 将 PDF 第一页渲染为 EPUB 封面图；第一页仍参与正文提取，不因生成封面而丢弃文字内容。

## V1 EPUB 内容结构

- UI 提供自动、可重排和固定双页三种模式，默认自动选择。
- 自动选择抽样检查主图片覆盖率、空文本和跨页重复文本层；图片型正文走固定版式，可靠正文文本走可重排版式。
- 固定版式按源页面生成等尺寸 viewport 和页面图像，在 OPF spine 中声明左右页、双页展开和从左到右翻页。
- 手动强制可重排时，图片型正文必须明确失败并提示改用固定版式，不能把水印当正文。

- 导航目录优先采用有效的 PDF 大纲并保留层级。
- PDF 没有有效大纲时，只根据明显字号层级、章节编号等高置信度特征推断章节。
- 无法可靠识别章节时，仅生成一个“正文”导航入口，不虚构章节。
- PDF 中的印刷目录页作为正文保留，但不直接等同于 EPUB 导航目录。
- 仅在高置信度时删除跨页重复出现的页眉、页脚和独立页码；置信度不足时保留，避免误删正文或脚注。
- EPUB 不复刻 PDF 的固定分页。
- 合并段落内部因 PDF 页面宽度产生的视觉换行，PDF 翻页本身不产生新段落。
- 根据首行缩进、行距和段间距识别真实段落边界；中文合并行时不插入空格，英文保留正常词间空格。
- 仅在高置信度时合并英文行尾断词；判断不可靠时保留原字符，不擅自改写正文。
- 普通插图按阅读顺序保留；简单表格优先转换为可重排的 XHTML 表格。
- 表格、图表或组合图形无法可靠结构化时，将对应区域渲染为图片并保留附近题注。
- 正文段落不得用整页图片降级；正文无法完整提取时，转换任务失败。
- 能高置信度匹配正文标记与页底注释时，生成可跳转并返回正文的 EPUB 脚注。
- 无法可靠匹配脚注时，不猜测关联；脚注文字按原顺序保留在对应页面正文之后，书末尾注章节按普通章节保留。
- 脚注识别失败不得导致文字被静默删除。
- 保留合法的 `http`、`https` 和 `mailto` 外部链接，但转换服务不主动访问目标。
- PDF 内部跳转只有在目标位置能可靠映射时才转换为 EPUB 内部链接。
- 无法映射或使用不安全协议时，移除链接能力但保留可见文字；链接失败不导致正文丢失或整本转换失败。
- 不从 PDF 提取或嵌入字体；EPUB 使用简洁的响应式 CSS，并由阅读器控制字体、字号和行距。
- 保留标题层级、段落、粗体、斜体、上下标、列表、表格和图片等语义样式，不复刻绝对坐标、固定字号或装饰性排版。

## V1 运行与安全边界

- V1 是可部署到服务器并供远程浏览器访问的 Web 服务。
- 监听地址和端口必须可配置，并允许在受控部署环境中监听非回环地址。
- 私有模式使用一个内置账号登录；公开付费 Beta 不展示密码登录，而是签发 HMAC 保护的长期访客会话。
- 账号、会话、支付、Turnstile 和 R2 密钥通过环境变量或密钥文件注入，不得写入源码、镜像、前端或仓库。
- 公开模式的任务、额度、订单和下载都绑定服务端 `subject ID`；任务 owner 不匹配统一返回 404，不能只依赖前端隐藏按钮。
- 公开模式在上传前检查额度，并要求 Turnstile 换取两分钟、一次性且绑定 subject 的上传票据；上传票据在读取 multipart body 前消费。
- 公开模式同时使用来源 IP 和 subject token bucket 限流；Cloudflare WAF/Rate Limiting、源站防火墙和容器资源限制仍是独立防线，应用限流不能替代边缘防护。
- 每个任务原子扣除 1 个整数额度；失败、取消或任务接受后的基础设施错误幂等退款，成功任务完成扣费。
- 支付回跳页面不产生额度；只有 Stripe webhook 通过时间窗和 HMAC 验签、与本地订单的 account/order/session 绑定一致且事件未处理时才入账。
- 公开模式缺少 Secure Cookie、HTTPS origin、支付、Turnstile、私有 R2 或持久化账本配置时必须拒绝启动，不能降级成匿名免费转换。
- PDF、转换中间文件和 EPUB 均在服务端处理和临时存储。
- 单个 PDF 最大 `100 MiB`、最多 `1000` 页；超限文件必须明确拒绝并显示实际值与允许上限。
- V1 不收集 PDF 密码；需要密码、采用加密保护或禁止提取内容的 PDF 必须在预检时明确拒绝。
- V1 支持横排简体中文、繁体中文、英文及中英混排；不承诺竖排、从右向左或其他语言排版的转换质量。
- 转换过程不主动访问 PDF 中的外部链接；只允许输出 `http`、`https` 和 `mailto` 链接能力。
- 远程暴露前必须明确身份认证、访问隔离、传输安全和文件清理策略。

## V1 部署边界

- 正式交付 Linux Docker 镜像和 `docker compose` 示例。
- 容器内监听地址可设置为 `0.0.0.0`，端口可配置。
- 生产环境由 Caddy、Nginx 或云负载均衡器终止 HTTPS，再转发到 Go 服务。
- PDF 处理与 EPUB 校验所需的系统工具封装进镜像，不要求部署者逐项手工安装。

## V1 文档工具边界

- Go 服务拥有领域流程、任务调度、内容重建和 EPUB 生成逻辑。
- PDF 解析和渲染通过 `go-pdfium` 的 WebAssembly 模式完成，不使用 CGO。
- PDFium WebAssembly 每次只能访问当前任务所需的隔离目录，不得挂载整个容器文件系统；任务结束后关闭实例以释放资源。
- 最终 EPUB 必须通过 Docker 镜像中封装的 W3C EPUBCheck 命令行工具校验。
- PDFium、`go-pdfium`、EPUBCheck 和 Java 运行时版本必须在构建配置中固定，并维护第三方许可证清单。

## V1 转换交互

- 一个转换任务只接收一个 PDF，并异步执行。
- 同一时刻只允许一个任务执行转换。私有模式默认不排队；公开模式默认允许 3 个等待任务，容量可配置但不得超过 20。
- 队列满时新任务必须明确返回 409；排队任务保持 `queued/waiting`，UI 显示等待状态，不制造处理进度。
- 上传成功后返回任务标识；任务状态为等待、转换中、成功、失败或已取消。
- 等待或转换中的任务可以由用户取消；取消必须停止转换及其子进程、立即清理 PDF 副本和中间文件、不生成 EPUB，并释放处理槽。
- 任务从进入转换中开始最多运行 30 分钟；超时必须终止转换及其子进程、标记为失败、显示转换超时、清理临时文件并释放处理槽。
- UI 根据任务状态展示进度或失败原因，并在成功后提供 EPUB 下载。
- UI 在任务未结束时每 2 秒轮询任务状态，进入终态后停止；页面处于后台时降低轮询频率。
- 进度展示预检、提取、内容重建、打包和 EPUB 校验等真实阶段；能可靠计算时显示已处理页数和总页数，否则只展示阶段，不制造总体百分比。
- 成功任务可以携带转换警告，UI 必须在下载前展示；警告不改变成功状态。
- 只有全部页面已处理、主要阅读顺序明确且 EPUB 通过规范校验时任务才能成功。
- 正文缺失、页面未处理、主要阅读顺序不明、EPUB 结构或规范校验失败、输出无法完整写入时，任务必须失败且不提供下载。
- 任务只在当前程序进程中有效，不跨程序退出或重启恢复。
- 任务状态不持久化，但额度、订单、支付事件和任务扣费账本使用独立 bbolt 文件持久化；启动时自动退款上一次进程遗留的未终态扣费；账本禁止放入启动时清空的任务工作目录。
- 程序仍在运行时，浏览器刷新可以使用任务标识恢复当前任务页面。
- 程序启动时清理上一次运行遗留的临时文件，不提供历史任务列表。
- 任务成功、失败或取消后，立即删除上传的 PDF 副本和转换中间文件。
- 成功生成的 EPUB、失败原因和终态任务状态自任务结束起保留 1 小时，期间允许重复下载或查看；到期后自动清理。
- 配置 R2 时，成功 EPUB 上传到私有 bucket 后立即删除源站副本；已认证下载接口生成短期签名 URL 并返回 302，浏览器直接从对象存储取回文件。
- 私有模式下 R2 上传失败时保留本地产物并显示降级警告；公开付费模式禁止回退源站下载，上传失败必须把任务标记为失败、清理产物并自动退回额度。
- R2 对象沿用任务的一小时保留期；正常到期和优雅退出都会请求删除远端对象，bucket 生命周期规则作为异常退出后的兜底。
- 程序退出时可以提前清理尚未到期的任务产物。
