# 公开付费 Beta 使用访客身份、额度账本和分层反滥用

## 状态

已接受。公开访问边界替代 ADR 0006 的“所有访问必须共享账号密码”；ADR 0006 继续约束默认私有模式。支付与挑战 provider 的强制选择，以及仅依赖 Cookie 的恢复限制，已由 ADR 0012 扩展。

## 决策

服务保留默认关闭的私有模式，并增加显式 `BTC_PUBLIC_ACCESS=true` 的公开付费 Beta。公开模式不展示密码登录，而是为浏览器签发 HMAC 保护、包含随机 `subject ID`、CSRF token 和到期时间的访客 Cookie。任务创建、状态、取消和下载全部按 `subject ID` 校验 owner，owner 不匹配统一返回 404。

每个转换任务成本固定为 1 个整数额度。单机 Beta 使用独立 bbolt 文件持久化账户、余额、不可变额度流水、订单、支付事件和任务扣费。任务管理器在接受任务时通过事务检查并扣减额度；成功完成扣费，失败、取消和接受后的基础设施错误按任务 ID 幂等退款。任务状态本身仍是进程内数据，重启不恢复转换队列；账本启动时会把上一次进程遗留的 `authorized` 扣费视为中断任务并幂等退款。

首个支付实现使用 Stripe Checkout。浏览器只请求服务端创建 Checkout Session，不能指定价格、额度或 account。支付返回页面只轮询余额，不直接发放额度；Stripe webhook 必须通过签名时间窗和 HMAC 校验，并与本地 order、account 和 Checkout Session 一致，事件 ID 未处理过，才在同一事务中完成订单与入账。支付网关使用接口隔离，后续可增加其他渠道。

公开上传需要先用 Cloudflare Turnstile token 调用小请求，服务端通过 Siteverify 后签发两分钟、一次性、绑定 subject 的上传票据。上传接口在读取 multipart body 前检查余额并消费票据。应用同时实施来源 IP 和 subject 限流；执行层保持一个工作器，默认只允许 3 个等待任务。Cloudflare WAF/Rate Limiting、源站防火墙、反向代理请求体策略、容器内存/PID/权限和 PDFium/超时限制继续作为独立防线。

公开模式缺少 HTTPS public URL、Secure Cookie、Stripe secret/webhook secret/Price、Turnstile site/secret、私有 R2 或持久化账本路径时拒绝启动。公开模式必须用 R2 交付成功产物，避免大文件下载消耗源站出口。

## 原因

直接删除共享密码会同时删除唯一的身份和成本边界，导致无法安全绑定余额、订单、任务和下载。单次极小额支付还会受到支付固定费用、退款和拒付成本影响，因此 Beta 使用可配置的额度包而不是每次跳转支付。只有边缘、应用、工作器和数据四层同时设限，才能避免 IP 轮换、任务 ID 越权、支付回放、解析器资源耗尽和队列饥饿。

## 限制与后续

- 当前访客额度绑定浏览器 Cookie；清除 Cookie 或更换设备后无法自助找回。正式扩大投放前增加邮件 magic link 和余额恢复，不能使用共享管理员密码替代。
- bbolt 只支持单机单写者。需要多个应用实例或工作器时，先迁移 PostgreSQL 和持久化任务队列。
- UI 的价格标签来自配置，实际扣款由 Stripe Price 决定；上线检查必须确认两者一致。
- 上线前必须补齐服务条款、隐私政策、退款/拒付流程、客服入口、监控告警与账本备份恢复演练。
